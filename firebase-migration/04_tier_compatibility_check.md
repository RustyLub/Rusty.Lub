# Проверка несовместимости между Firestore Enterprise и Standard

Данный документ описывает проверки на совместимость при переносе базы данных между проектами с одинаковым Database ID (`ai-studio-rustylub-2e66bd8d-85dd-4eba-bb83-f354ddc97d59`).

## 1. Сравнение параметров
- ** Database ID:** В обоих проектах используется пользовательский ID базы данных (`ai-studio-rustylub-2e66bd8d-85dd-4eba-bb83-f354ddc97d59`). Это гарантирует, что пути к документам и клиентские инициализации останутся абсолютно идентичными.
- **Тарифный план (Spark Free Tier):**
  - Ограничение на чтение: 50,000 документов в день.
  - Ограничение на запись: 20,000 документов в день.
  - Ограничение на удаление: 20,000 документов в день.
  - Хранилище: 1 ГБ.

## 2. Потенциальные несовместимости
1. **Типы данных Timestamps:** При экспорте через JSON дата-типы `Timestamp` и `FieldValue.serverTimestamp()` могут преобразовываться в строки ISO 8601 или объекты `{ _seconds, _nanoseconds }`. При импорте в новый проект важно восстановить их тип через Admin SDK, чтобы не нарушить сортировку сообщений и даты создания.
2. **Индексы Firestore:** Пользовательские индексы (composite indexes) не переносятся автоматически вместе с данными через простой JSON-экспорт. Их необходимо пересоздать в новом проекте через `firestore.indexes.json` или вручную в консоли Firebase.
